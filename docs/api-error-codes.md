# 接口错误码约定

后端统一返回体为 `R<T>`：`{ "code": number, "msg": string, "data": T }`。
HTTP 状态码与 `code` 保持一致的语义，便于前端拦截器与网关监控区分失败类型。

| HTTP | code | 场景 | 触发点 |
|------|------|------|--------|
| 200 | 200 | 成功 | 正常返回 |
| 400 | 400 | 参数校验失败 / 业务规则不满足 | `@Valid` 校验、`BusinessException` |
| 401 | 401 | 未登录 / 令牌失效 | Sa-Token `NotLoginException` |
| 403 | 403 | 已登录但无权限 | Sa-Token `NotPermissionException`/`NotRoleException` |
| 500 | 500 | 系统异常（堆栈不外泄） | 未捕获异常 |

约定细则：

1. **业务失败用 400**：可预期的规则不满足（重复用户名、弱口令、状态非法等）抛 `BusinessException`，
   默认 `code = 400`，由全局异常处理器映射为 HTTP 400。
2. **系统故障用 500**：未预期异常统一返回 HTTP 500 + “系统繁忙，请稍后重试”，
   日志记录完整堆栈，响应体不包含堆栈或内部类名。
3. **认证/授权分开**：401 表示“你是谁未知”，403 表示“你是谁已知但无权限”。
4. 前端 `src/api/request.ts` 仅对 `code === 401` 做清理会话并跳登录，其余失败直接弹出 `msg`。
